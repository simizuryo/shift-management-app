# シフト管理アプリ 要件定義書

## 1. 概要

- **背景**: プログラミングスクール等の課題として本アプリを開発する。実務上の課題解決を目的としたものではなく、学習目的が主眼である
- **目的**: シフト(勤務予定)の登録・閲覧を行うシンプルなWebアプリケーションを題材に、CRUD処理やデータ設計、画面設計といった基本的なアプリケーション開発の流れを一通り習得する
- **スコープ方針**: 学習目的のため、機能の網羅性よりも基本的な実装を最後までやりきることを優先し、v1では必要最小限の機能に絞る

## 2. 対象ユーザー

- 開発者本人による単一ユーザーでの利用を想定する
- 認証・権限管理・複数ユーザーでの共有は行わない(v1スコープ外)

## 3. 用語定義

| 用語 | 意味 |
|---|---|
| シフト | 特定の日付・時間帯に割り当てられた勤務予定を表す1件のデータ |
| シフト表 | 登録されたシフトの一覧・カレンダー表示 |

## 4. スコープ

### 4.1 v1に含む機能(コア機能)

- シフトの登録(作成)
- シフト表の閲覧(一覧表示)
- シフトの削除(1件ずつ、削除前に確認あり)
- シフトの編集(専用の編集画面で行う)

### 4.2 v1では対象外とする機能(将来の拡張候補)

- 複数ユーザー・認証機能・権限管理
- 勤務先/シフトパターンのマスタ管理
- シフトの希望提出・承認フロー
- 労働時間の集計・給与計算連携
- 通知・リマインド機能
- 他カレンダーサービス(Googleカレンダー等)との連携

> v1リリース後の状況を見て、上記の中から優先度の高いものを段階的に検討する。

## 5. 機能要件

### 5.1 シフト登録機能

| 項目 | 内容 |
|---|---|
| 概要 | 新規シフトを1件登録する |
| 入力項目 | 日付(必須)、開始時刻(必須)、終了時刻(必須)、メモ(任意・勤務先や業務内容など自由記述) |
| バリデーション | 日付・開始時刻・終了時刻は必須。終了時刻は開始時刻より後であること |
| 完了時の挙動 | 登録後、シフト表(一覧)に反映される |

### 5.2 シフト表閲覧機能

| 項目 | 内容 |
|---|---|
| 概要 | 登録済みのシフトを一覧表示する |
| 表示項目 | 日付、開始時刻〜終了時刻、メモ |
| 並び順 | 日付・開始時刻の昇順 |
| 表示形式 | v1ではシンプルな一覧(リスト/テーブル)表示とする。カレンダー形式のUIは将来の拡張候補とする |

### 5.3 シフト削除機能

| 項目 | 内容 |
|---|---|
| 概要 | 登録済みのシフトを1件ずつ削除する |
| 操作 | シフト表(一覧)の各行にある「削除」ボタンから行う |
| 確認 | 誤操作防止のため、削除前に確認ダイアログを表示する。キャンセルした場合は削除しない |
| 完了時の挙動 | 削除後、シフト表(一覧)から該当シフトが消える |

### 5.4 シフト編集機能

| 項目 | 内容 |
|---|---|
| 概要 | 登録済みのシフトを1件編集する |
| 操作 | シフト表(一覧)の各行にある「編集」ボタンから、専用の編集画面に移動して行う |
| 入力項目・バリデーション | 5.1 シフト登録機能と同じ |
| 完了時の挙動 | 更新後、シフト表(一覧)に反映される |

## 6. 非機能要件

- **想定利用環境**: PCブラウザでの利用を主とする(モバイル対応は必須としない)
- **データ永続化**: アプリ再起動・再読み込み後もシフトデータが保持されること
- **性能**: 個人利用規模(数十〜数百件程度のシフトデータ)を想定し、特別な性能要件は設けない
- **セキュリティ**: 単一ユーザー・ローカル利用を前提とし、認証・通信暗号化等は必須要件としない

## 7. 画面構成(想定)

| 画面 | 内容 |
|---|---|
| シフト一覧画面 | 登録済みシフトの一覧表示・削除、編集画面への導線、新規登録フォーム(または登録画面への導線) |
| シフト登録画面(またはモーダル) | 日付・時間帯・メモを入力してシフトを登録する |
| シフト編集画面 | 登録済みシフトの日付・時間帯・メモを修正する |

> 画面遷移・詳細なUIレイアウトは今後の設計フェーズで詳細化する。

## 8. データ設計(概略)

### shifts(シフト)

| カラム名 | 型(想定) | 説明 |
|---|---|---|
| id | 識別子 | 主キー |
| date | 日付 | シフトの日付 |
| start_time | 時刻 | 開始時刻 |
| end_time | 時刻 | 終了時刻 |
| memo | 文字列(任意) | メモ・備考 |
| created_at | 日時 | 作成日時(Rails標準) |
| updated_at | 日時 | 更新日時(Rails標準) |

> v1は単一ユーザー利用のため、ユーザーIDでの紐付けは行わない。

## 9. 技術スタック

| レイヤー | 技術 | 選定理由 |
|---|---|---|
| フロントエンド | Next.js(App Router) | 指定による。Reactの知識がそのまま活かせる |
| バックエンド | Ruby on Rails(APIモード) | 指定による。少ないコード量でAPIを構築できる |
| データベース | SQLite(Rails同梱) | 指定なしのため、インストール不要・無料のファイル式DBを選定。将来MySQL等へ切替可能(`database.yml`とGemfileの2箇所を変更すれば対応できる) |

- フロントエンド(Next.js)とバックエンド(Rails API)は別プロセスとして構成し、フロントエンドからRailsのAPIをHTTP経由で呼び出す構成とする
- 詳細なバージョン・依存パッケージ等は、実装着手時に別途決定・記載する
