# 画面設計

[要件定義書](./requirements.md) の「5. 機能要件」「7. 画面構成(想定)」を具体化したもの。v1は以下の2画面構成とする。

## 画面一覧

| 画面ID | 画面名 | パス(想定) | 概要 |
|---|---|---|---|
| A | シフト一覧画面 | `/`(トップ) | 登録済みシフトを一覧表示する |
| B | シフト登録画面 | `/shifts/new` | 新規シフトを登録する |

## 画面A: シフト一覧画面

```
┌─────────────────────────────────────┐
│ シフト管理アプリ                       │  ← ヘッダー
├─────────────────────────────────────┤
│                          [+ 新規登録] │  ← 画面Bへの導線(右上ボタン)
│                                       │
│ 日付       時間          メモ   操作  │
│ ─────────────────────────────────── │
│ 2026/09/25 09:00-17:00 レジ対応 [削除]│
│ 2026/09/26 13:00-18:00          [削除]│
│ 2026/09/28 09:00-17:00 棚卸し   [削除]│
│  ...                                 │
└─────────────────────────────────────┘
```

- **表示範囲**: 全件表示する(過去分を含む、期間フィルタは持たない)
- **並び順**: 日付・開始時刻の昇順(要件5.2)
- **表示項目**: 日付、開始時刻〜終了時刻、メモ
- **空状態**: シフトが0件の場合は「まだシフトが登録されていません」というメッセージと、画面Bへの導線ボタンを表示する
- **画面Bへの導線**: 右上に「+ 新規登録」ボタンを配置し、クリックで画面Bへ遷移する
- **削除**: 各行の右端に「削除」ボタンを配置する(要件5.3)。クリックすると「2026/09/25 09:00-17:00 のシフトを削除しますか?」という確認ダイアログを表示し、OKで削除して一覧を更新する。キャンセル時は何もしない。削除に失敗した場合はボタンの下にエラーメッセージを表示する

## 画面B: シフト登録画面

```
┌─────────────────────────────────────┐
│ ← 一覧へ戻る                          │
│                                       │
│ シフトを登録                          │
│                                       │
│ 日付       [____________]            │
│ 開始時刻    [____________]            │
│ 終了時刻    [____________]            │
│ メモ(任意) [____________________]    │
│                                       │
│              [キャンセル] [登録する]   │
└─────────────────────────────────────┘
```

- **構成方針**: 独立ページとする(モーダルにはしない。v1はシンプルさ優先)
- **入力項目**: 日付(必須)、開始時刻(必須)、終了時刻(必須)、メモ(任意)
- **バリデーション**: 日付・開始時刻・終了時刻は必須。終了時刻は開始時刻より後であること(要件5.1)。エラーはフォーム直下にメッセージ表示する
- **登録後の遷移**: 登録成功後は画面A(一覧)へ自動で遷移する
- **キャンセル**: 「キャンセル」ボタンまたは「← 一覧へ戻る」リンクから、入力内容を破棄して画面Aへ戻る

## 画面遷移図

```
画面A(シフト一覧) --「+ 新規登録」--> 画面B(シフト登録)
画面B(シフト登録) --「登録する」(成功)--> 画面A(シフト一覧)
画面B(シフト登録) --「キャンセル」/「← 一覧へ戻る」--> 画面A(シフト一覧)
画面A(シフト一覧) --「削除」→ 確認ダイアログでOK --> 画面A(該当シフトを除いて再表示)
```
